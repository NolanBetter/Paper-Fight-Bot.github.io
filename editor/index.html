Getting a link

  1. Join your server, or open its console.
  2. Run /fightbot web. It takes a few seconds to make.
  3. Open the link it gives you. It works for 30 minutes unused, 4 hours in all.

You need FightBot 5.17.2 or newer and the fightbot.web permission. How to install it.

Read only. This server has web.read-only switched on, so you can look but not change anything.

Tell it what to do

This bot’s own switches

Every one of these starts out following your config.yml. Flip one and this bot alone changes — until it dies or the server restarts.

Bots are spawned in game, by someone with fightbot.use, not from here. Type /fightbot spawn on the server.

Bots on the server

Groups

A bot is in one group at a time. Click a group to see who is in it. Groups keep their names across a restart, but they start empty, because bots do not survive one.

Routes

Routes are laid out in game, where you can stand on each point: /fightbot roamingroutecreate <name>, then /fightbot roamingpointset <name> on every spot. Click one to send bots along it.

Kits

A kit re-gears bots you already have. Click one, then click the bots to give it to.

Saves

A save keeps a bot’s gear and its settings. Because a save spawns bots, FightBot only lets you make, use and delete one in game: /fightbot savegear <bot> <slot> and /fightbot save <slot>. Here they are, so you know what is stored.

Add a skin

A Minecraft skin image: a 64×64 PNG, or an old 64×32 one. New images are signed automatically, which takes a few seconds each. Bots only wear this folder while identity.skin-source is folder.

Skins folder

Voice lines

Files added here are only ever played when someone asks — never by a bot on its own. Everyone near the bot sees that it’s a sound file added by this server, and who played it.

Add a line

MP3 or WAV. Anything else — a phone’s .m4a, an .ogg, a .webm — is converted in your browser first. The name you give it is what you type in game: /fightbot vc <name>.

Debug logging

Every decision the bots make, written to plugins/FightBot/debug/. Leave it off unless you are chasing a bug — then turn it on, make the bug happen, and attach the log to a report.
